## Регрессии, проверенные 4 ноября

- Адрес отеля длиной 500 символов и описания отеля/номера длиной 2000 символов
  сохраняются в H2; превышение лимитов возвращает 400 без создания записей.
- Неизвестный маршрут возвращает 404 с traceId, неверный метод — 405 с Allow,
  неподдерживаемый Content-Type — 415 с Accept. Неожиданная ошибка остаётся 500
  без раскрытия деталей клиенту. Проверено сохранение нестандартного статуса и заголовков.
- Конфликт уникальности номера возвращает 409 с сообщением о конфликте данных,
  которое не приписывает всем нарушениям БД одну причину.
- Восемь тестов конкурентности Booking используют H2 и подмену HotelClient:
  независимые брони выполняются параллельно; одинаковые ключи не дублируют выделение;
  владельцы изолированы; устаревшие retry/recovery перечитывают состояние; новая отмена
  сохраняет свежий JWT; последняя попытка компенсации расходуется один раз;
  параллельное сохранение токенов соблюдает ограничение памяти.
- Существующие HTTP-тесты Booking, конкурентные тесты Hotel и проверки безопасности
  Gateway повторно прошли без изменения ожидаемых гарантий.

## Независимая проверка

Проведён отдельный review конкурентности, компенсаций и авторизации. Найденная гонка
между отменой и подтверждением исправлена: DB row lock, переход только из PENDING,
HTTP вне транзакции; сценарий включён в интеграционные тесты. Проверены опоздавшие
HTTP-ответы, release-before-reserve, повторная доставка и истёкшие учётные данные компенсации.

4 ноября глобальный монитор BookingService заменён ограниченным набором блокировок
по владельцу и requestId. Сетевой вызов одной брони больше не блокирует весь сервис.
При совпадении индекса блокировки разные брони могут ждать друг друга; операции одной
брони сериализованы. HTTP по-прежнему выполняется вне локальной DB-транзакции.

## Границы проверки

Это проверка учебного проекта, не аудит production и не гарантия оценки. Не тестировались
нагрузочное масштабирование, долговечная внешняя БД и независимый рестарт сервисов без потери
данных. H2 in-memory сбрасывается при остановке; перезапускать демонстрацию следует целиком.
При истечении JWT или исчерпании компенсаций требуется повторная отмена владельцем с новым JWT.
Демонстрационные пароль и ключ публичные; для эксплуатации их использовать нельзя.
